# 输入、确认、审计、交付与状态

工作区结构为 `state/`、可选 `merchant_rules.json` 与 `YYYY.M/`。账期内使用 `原始数据/`、`处理结果/`、`执行记录/` 和最终 Excel。包内模板不承载用户数据；缺失状态首次更新时生成，已有状态不被空模板覆盖。

预处理使用 `--root / --period / --files / --output`；`--mapping` 必需。外部文件先复制登记到当期原始目录，保留原名、SHA256；同名不同内容追加哈希后缀。证据只使用工作区相对 POSIX 路径。`--output` 是工作区内的隔离预处理目录，正式流程使用标准账期目录。无显式账期时，上传内容须唯一确定月份；无上传时按数值年月选择最新未处理或源文件变化的目录。

`原始标准化.json` 保留每个证据行与合并后的投影。重叠导出只在明确账户、来源与真正稳定交易 ID 一致且事实一致时归并，保留全部位置；冲突不抹除。字段映射进入源清单以便 validator 从源文件重新解析并复核原始字段。`预分析.json` 与启动日志只作工作材料。

Agent 依包内自定义 schema 的 `contracts` 构建四类事实输入：经济事件、关联、确认、当期上下文。不是标准 JSON Schema，不另建第二套字段定义。每份文件为 2.0 版本并带 period_id。参考合成测试的输入结构可以帮助理解，但合成语义不适用于真实账单。

经济事件使用 `record_allocations` 表达主流水、重复证据与资金来源；一个流水可拆为本金和费用等多个事件，每个分配有独立金额。当期流水必须完整分配。内部备注 `audit_notes` 仅留事实层，不属于实体的审计展示字段。

确认记录保留问题、答复、受影响记录/事件 ID 和证据。`analysis_context.json` 仅保存本期范围、观测日、币种/精度、完整性、确认引用以及本期目标/义务变更。它不承载商户规则、匹配阈值、未来运行参数或人工指标覆盖。完整覆盖的声明引用确认 ID；交易日期范围不自动证明完整性。

结构化事实文件会被后续修订。Agent 用 `common.ref(root, path, record_ids=[...])` 或 confirmation_ids/event_ids 生成证据引用；该函数先将处理结果/确认的原样字节保留为 `执行记录/审计快照/<SHA256>-<原名>.json`，返回相对路径与哈希。这些快照是不可变的用户审计数据，不能删除或改写。正式事实与长期状态引用快照，避免复核时破坏旧修订链；report_data.input_manifest 仍引用当前事实文件，以检查陈旧输入。原始文件直接引用已登记的原始位置。

可执行事实审计核查版本、所有嵌套字段、原始来源与哈希、坐标、ID 引用、分配、经济净额、关联额度、目标接受和义务生命周期。未读取文件或拒绝行存在时，收支完整性不能标 complete。缺证据、路径越界、哈希变化、重复分配都阻止正式链。

prepare 只生成 `report_data.json` 和 `report_copy.draft.json`，不替 Agent 审核正式结论。Agent 审核静态文案及动态段落，保存 `report_copy.json`。文案 `data_sha256` 是 report_data 的规范 JSON 摘要，不能手写任意固定值；可通过 `common.digest` 计算。动态段落用 `{metrics.net_expense.value:.2f}` 等标量路径占位符，并列入 data_refs；条件只引用状态字段。缺值显示模板的 missing 文案。

所有可见标题、表头、解释与注释来自 report_copy.strings/sections。原始摘要、经济分类、坐标与状态作为已审计事实来自 report_data 的实体白名单投影。metrics.definition 是口径审计字段，不直接显示说明；需要展示时经审核放入文案。自由日志、问答原文、内部备注、临时文字不进入渲染函数。

`load_report_inputs(root, period)` 重审事实与状态，校验两份输入，检查文件摘要并重新计算全部 report_data；修改报告数字并更新文案摘要仍不能绕过。render 函数仅收两个对象。Excel 用数值、筛选与明确格式，不依赖公式缓存、外部计算引擎或固定字体路径。核心页、原始/标准化、事件、关联与长期反馈均保留。

render 保存 Excel 后逐页读回核对，并写入 `交付审计.json` 的报告及成品摘要。审计通过后 update_state 再核验工作簿，按 ID 更新。摘要修订由程序保留前后快照；目标/义务事实变更须由 Agent 提供准确 revision 并保留旧链。已接受目标的数值反馈由程序判定并留修订；条件目标须有明确完成确认，否则降级。

源证据被修改后需重新分析和审核；不要改写已保存证据文件来绕过哈希。工作簿是交付快照，后续修改须回到事实链重新生成。不自动迁移其他数据格式，也不合并不同币种的金额。
